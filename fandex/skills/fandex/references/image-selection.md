# 选图审美标准（封面 / 肖像）

工具解决不了审美。这份文档是选图的判断依据——**核心原则一句话：有戏 > 清晰**。清晰度只是及格线；一张高清的证件照永远输给一张有表情、有环境、有故事的图。

## 封面图（`cover`）——要"海报感"

上封面瓦片、也决定该章主题色（自动取色基于它）。

**要：**
- **有环境**：天空、场景、道具。背景最好能讲人设——例：大胃王角色配食物环绕的插画，背景本身就是人物小传
- **有动态**：伸手、回头、大笑、被拽走、奔跑。动作和表情是"戏"
- **构图完整**：脸部落在画面上方 1/3–1/2；人物占画面约 60%
- **单人正面主体**（瓦片是单人位，合影不适合）
- 色彩与角色标志色同调（主题色会从这张图提取，图和色互相成就）

**避：**
- 纯白/透明底立绘（"洗成色块"只是补救，原生带背景才好）
- 静止站立、正装照、证件照式半身像
- 头/下巴/手被裁断
- 带宣传文字、logo、水印（"2024.7 On Air"这类；能裁掉再用）
- 动画截图（噪点多、构图随意）；**同人图**（授权不清，不必碰）

## 章节肖像（`portrait`，可选）——要"立绘感"

上章节页左侧的肖像位。**和封面要求相反**：这里背景干净反而好、主体安静、细节清晰。

**要：**
- 人物为主、背景干净（白底可，本书给肖像位配了主题色渲染，不会显白）
- **正脸或 3/4 侧脸、眼神可见**
- 半身或全身立绘
- 高分辨率

**避：** 背影、侧脸遮挡、裁剪混乱、带文字。

> 缺省规则：不给 `portrait` 就自动用 `cover`（旧行为）。给角色配齐两张时，封面用氛围图、章节用干净立绘，效果最好。

## 来源优先级

分两步定：**先去哪儿拿（渠道）**，再决定**拿哪张（素材）**。渠道错了，素材再好也是授权不明的一张图。

### 一、渠道：官方优先，图库兜底

1. **一手官方渠道（首选）**——版权链最干净，画质也是母版：
   - 动画官网 / 制作委员会 / 发行方 的角色页与特设页；官方 X（Twitter）、官方微博公布的版权绘
   - 原作出版社特设页、小说插画师本人公开的作品页（**原作插画常只在这里**）
   - 官方 Blu-ray / 专辑 / 活动主视觉
2. **二手汇总渠道（次选）**——好找，但要回溯：AniList 条目 `coverImage`、Bangumi 条目封面、维基条目配图。用它们**定位**到图，能回到官方原页就用官方那份
3. **safebooru 的 `official_art` 池（兜底 · 仅对比）**——**不作为首选来源**：
   - 它唯一不可替代的价值是"一次拉一批同类图做横向比较"（`npm run candidates` 就是干这个的）
   - 图站是用户上传，**授权与来源不透明**；选中的图应尽量回溯到官方原图再入库
   - 查询已排除 `rating:explicit` / `rating:questionable`，但那只是兜底，最终以目视为准

### 二、素材：什么图适合上封面

1. **原作插画**（小说插画师的原作图）——笔触与构图质量最高，且是作品的门面
2. 动画官方图 / 版权绘
3. 官方海报（注意裁掉宣传文字）
4. 动画截图（最后手段）
5. 同人图——**不用**（授权与质量都不可控）

> 需要横向比一批同类图时才用 `npm run candidates -- <safebooru_tag> [...]`——按上面的优先级，它属于**兜底**那一步。

### 法律红线（优先于一切审美）

- **擦边/露骨素材一律弃用**：命中 R-18 / questionable 的图直接换源。`npm run candidates` 的查询里已排除 `rating:explicit` 与 `rating:questionable`，但那只是兜底——**最终以目视为准**，尤其注意"画风可爱但内容性化"的情况。这类内容的法律后果是刑事级，不是版权级
- **不用同人图**：授权链条不清（见上方"避"清单）
- **不用真人素材**：声优照片、真人演员肖像涉及肖像权，本书只放角色图
- 官方美术（海报/版权绘/截图）**仅可用于个人收藏**；公开发布前需取得授权，成品封底的「非官方粉丝作品 · 仅供个人收藏」声明不要删

## 工作流（固化）

> 前提：**官方渠道（官网 / 官方 X / 发行方 / 原作出版社）已经找过、确实没有合适的图**，或者需要横向比一批同类图。否则先用官方渠道的图，不用往下走。

```bash
# ① 抓候选：按角色标签拉图 → 自动评分 → 出编号对比图（覆盖式，一次一个角色）
npm run candidates -- yanami_anna
#    → anime_build/_candidates/sheet.png（编号 00 起，绿字=有背景，黄字=白底）

# ② 看图挑编号（拼图按封面瓦片比例裁切，所见即所得）

# ③ 取选中的原图入库（加 --as <作品名> 可把这条来源归属到该作品）
npm run candidates -- --pick 04 --keep-top 0.79 --as <作品名>
#    → anime_research/covers/picked.jpg（固定名，--keep-top 裁掉底部宣传字区）
#    然后改名到 <角色名>.jpg，在 research JSON 的 cover / portrait 里引用
#    --pick 会自动往来源台账记一条「图库 safebooru + 原图地址」

# ④ 官方渠道取的图，手工记一条来源（合规台账）
npm run sources -- add --work <作品名> --kind cover --channel official --url <官方页面 URL>
#    交付前：npm run sources → anime_build/_sources.md（公开分享时核对授权用）
```

**目检不可省**：拼图出来后逐张看——是否本角色、表情是否有戏、构图是否完整、有无文字。名字相近的角色极易串味（Hades → Hades II 式错误）。

> **选中后回溯官方原图**：`--pick` 取的是图站上那一张；如果能找到官方发布页的同图，**优先用官方版本入库**（授权链更干净，分辨率通常也更高）。找不到再退回图站版本。

> 脚本产物用固定文件名是**刻意的**（避免命令行输入进入文件路径）；批量抓多个角色时逐个跑、每次把 sheet.png 另存后继续。

## 和主题色的关系

- 主题色默认**从封面图提取**（主导色相 + 固定明度）；封面选得好，色彩系统就成立
- 角色有公认标志色时（发色、主题道具色），可用 `research.accent` 手动指定覆盖——当四张封面都偏同一色调（例：都偏蓝）时，用标志色能让整版活起来
- 封面瓦片自带主题色渲染层（multiply），所以白底图也能用，但**能用带背景的就别用白底**
