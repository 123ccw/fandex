# 领域包：novel —— 小说设定集 / 伏笔手册

把同一台排版引擎用在小说上：**数据字段结构与番剧模式完全一致，只有语义和界面标签不同**。`config.json` 设 `"domain": "novel"` 后，所有"部/集/首播/系列收录"自动变为"位/章/初登场/伏笔回收"。

## 核心映射（research JSON 每个字段在 novel 模式下的含义）

一个 research JSON = **一个角色**（或一个势力/一件法器等设定单元），文件名 = 角色名：

| 字段 | novel 语义 | 界面呈现 |
|---|---|---|
| `title_zh` / `title_jp` | 角色名 / 别名·罗马字 | 章节大标题 / 副题 |
| `cover` | 立绘/头像（无也可，自动降级为纯排印；novel 下 `check` 不会因未声明 cover 判 `[C7]` 失败，但**声明了却找不到文件仍会失败**）；**建议配两张**：cover=有环境/动态的氛围图（上封面），portrait=干净正脸立绘（上章节页） | 左侧海报位 / 封面瓦片 |
| `portrait` | 章节页肖像（可选，缺省回退 cover）；选图标准见 `image-selection.md` | 章节页左侧肖像 |
| `accent` | 角色印象色（不填自动从立绘取色） | 全章主题色 |
| `synopsis` | 角色小传，建议 300-500 字（硬线 <120 或 >800 会报 `[A8]`） | 「角色小传（剧透注意）」 |
| `genres` | 阵营/种族/定位标签（4-6 个） | 标签胶囊 |
| `production` | 「身份：…；外貌：…；口癖：…；主要关系：A（师徒）、B（宿敌）」 | 结构化设定表（键值自动拆分） |
| `units` | 登场卷/篇：`{"name":"第一卷","eps":40,"airdate":发布日期ts}`（eps=该卷章数） | 出场详情表 |
| `unit_synopses` | 该篇中此角色的弧线（name 与 units 逐字一致） | 「弧线（含剧透）」列 |
| `watch_order` | 出场顺序（多作品联动时先后） | 「登场顺序」卡 |
| `music` | 重要关系一句话（配 production 的关系表用） | 「重要关系」行 |
| `platforms` | 登场卷/联动作品 | 「登场卷」行 |
| `status` | 角色当前状态（存活/退场/未登场/已完结弧线） | 状态徽章（含"已完结"=灰、含"连载中"=绿） |
| `update` | 该角色近期动态 | 「近况」卡 |
| **`franchise`** | **伏笔表**：`{"name":"伏笔名","kind":"明线/暗线","year":"埋设章节","collected":是否已回收}` | 刊头「伏笔进度 M/N」+ 章末「未回收」清单 + 数说页「待回收伏笔」 |
| `quote` | 角色金句 `{text, speaker}` | 台词卡（人设锚点） |
| `rating` | 可放角色强度/喜爱度等自定义评分 | 评分行 |

## 工作流（与番剧模式的差异）

1. **离线**：没有联网调研环节。让 agent 读你的设定笔记/草稿/大纲文件，按上表整理成 `anime_research/<角色名>.json`（文件名建议就用这个目录名，减少改动成本）
2. `names.txt` 一行一个角色名 → `npm run base` 合成 base
3. 字体子集与构建同番剧模式：`npm run pipeline`（自定义书名记得配 `config.json` 的 `title`，如《XX 设定集》）
4. 交付物同款：封面封底、数说页、`npm run cards` 档案卡 PNG

## 读者版脱敏技巧

同一份数据出两本：**作者版**全字段；**读者版**把 `unit_synopses` 留空（剧透表整列自动隐藏）、`franchise` 不给（伏笔进度不出现）、`synopsis` 只写无剧透部分——降级机制自动完成裁剪，不需要改任何代码。

## 质检要点（novel 特有）

- 伏笔表 `collected:false` 的条目是**你自己的待办**——数说页「待回收伏笔」块就是为此存在的，发书前过一眼
- 角色名与笔记文件名不一致时，`npm run base` 的模糊兜底按 folder/title 匹配，仍对不上会列出缺名单
- 时间轴按每个角色首个登场日期分列，多人同卷会叠在同一列（竖排可叠放）
