# 调研契约（给调研子代理的执行边界）

> 主文件按需指到这里。**派子代理之前先读这份**；`fields.md` 讲"每部要写什么字段"，这份讲"谁来写、写到哪、写不出来怎么办"。
>
> 为什么需要它：并发调研是这本书最贵的一步（每部都要联网查证 + 核图）。没有明确契约时，子代理会把结果写在对话里而不是落盘、会互相覆盖对方的文件、失败后没人知道该补哪一部。

## 一、分工单位：一部作品一个子代理

- **并发 ≤ 2**（实测超过会被宿主杀掉），**一次派 3-4 部**最省 token
- 每部一部作品的产出是**两个文件**，只准写这两个：
  - `<项目根>/anime_research/<作品名>.json`（字段见 `fields.md`）
  - `<项目根>/anime_research/covers/<作品名>.jpg`（官方海报，下载后必须目视核对）
- **绝对不要**让子代理写 `anime_base.json`、`names.txt` 或别人的 JSON——那是主 agent 的活，并发写同一个文件必坏

> `<作品名>` 用 `names.txt` 里的原名**逐字**（这就是 `folder` 字段的值）。改名会导致 `[C3]` 找不到调研稿。

## 二、给子代理的 prompt 必须包含的六件事

1. **要做的作品名**（一个，逐字给出），以及它是 TV / 剧场版 / OVA / galgame
2. **要读的文件**：`references/fields.md`、`references/pipeline.md` §一（数据源用法）、`assets/research.template.json`
3. **要写的两个路径**（绝对路径，写死在 prompt 里）
4. **取数规矩**：AniList 用罗马字/英文名搜并**核对返回的 `title`**；维基一律经 tvly 抓（本机直连返回空）；曲名/人名常挂在标题行下一行
5. **查不到就写「未核实（截至 YYYY-MM）」**，并在 `note` 里写清用了哪个查询、命中到什么——**宁可留痕，不要编**
6. **收尾要求**：写完文件后回报**一句话**：作品名 + 两个文件是否落盘 + 缺了哪些字段 + 封面文件名

> 第 6 条是"代理挂掉也能救"的关键：**汇报挂在落盘之后**，所以汇报失败不等于工作丢了。

## 三、子代理回报的格式（让它照抄这段）

```
作品：<作品名>
调研稿：已写 <绝对路径>（或"失败：<原因>"）
封面：covers/<文件名>（或"未取到"）
字段缺口：music、platforms（或"无"）
存疑：<需要主 agent 复核的点>
```

## 四、失败与重试

| 现象 | 处理 |
| --- | --- |
| 子代理被 killed / 超时 | **先查文件在不在**（`anime_research/<作品名>.json` 存在且不是半截）——常见"汇报时挂、稿子已写完"。文件完整就保留，只补缺失字段 |
| 回报"失败"，但文件在 | 同上：以**文件**为准，不以汇报为准 |
| 文件不在或 JSON 坏 | 重派这一个（不要重派整批）。同一个作品连续失败 2 次就停下来问用户，别无限重试 |
| 目录里出现多余的 `<作品名>.json.part` / `.tmp` | 删掉；只有完整 JSON 才算产出 |

**验收靠脚本，不靠感觉**：子代理报完就跑

```bash
npm run audit     # 逐部列出缺必填 / 还是"未核实" / 剧透表对不对得上；并写 receipts/<作品名>.json
```

`anime_build/receipts/` 下每部一份收据（状态 `complete` / `soft` / `hard` / `missing` / `broken` + 调研稿哈希），这就是"哪几部做完了、哪几部要重派"的可续跑清单——**中断后从 `hard` 和 `missing` 里挑，不用重新扫全书**。

## 五、字段归属：谁写什么

| 字段 | 谁写 | 说明 |
| --- | --- | --- |
| `anime_base.json`（`genres` / `units` / `airdate` / `cover` 等） | **主 agent** | 模式 A 由 `npm run base` 从 `names.txt` + 各 research 合成；模式 B 由自备扫描脚本生成 |
| 调研稿的全部字段（`synopsis` / `production` / `music` / `platforms` / `unit_synopses` / `franchise` …） | 子代理 | 见 `fields.md` |
| 图片文件 | 子代理下载，**主 agent 目视核对** | 「封面必须亲眼看」是主 agent 的责任，不能外包给子代理的自我声明 |
| 统计数字（集数/卷数/评分/跨度） | 子代理填，**主 agent 抽验** | 数字错了整页都错，且不会触发任何断言 |

## 六、成本与规模

- 成本主要在**联网查证 + 核图**，不在渲染：**5-20 部体验最好**
- 上百部请分批：`names.txt` 拆成 `names-01.txt`、`names-02.txt`，一次只让一个批次出现在 `anime_base.json` 里，做完一本再换下一批（**一本一个项目根**，不要试图在一本里塞 200 部——调研周期会拖到没法维护）
- 每批做完先 `npm run audit` 看硬问题数量，再决定要不要进下一批
